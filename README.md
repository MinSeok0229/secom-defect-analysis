# SECOM 반도체 공정 불량 예측 & 핵심 센서 도출

반도체 공정 센서 590개로 웨이퍼 불량(Pass/Fail)을 예측하고, **불량에 영향을 주는 핵심 센서를 찾는** 프로젝트.
통계 검정 → 선형 모델(Ridge/Lasso/Elastic Net) → 트리 모델(LightGBM + SHAP) → MLP를 **같은 교차검증 분할**에서 비교했고, 랜덤 CV(10-fold × 5회)와 **시간순 검증**을 함께 사용했다.

## 핵심 결과 한눈에

| 랜덤 CV | Lasso **31.7%**, LightGBM 31.8%, Elastic Net 32.7% (BER) → 기준선(F-test 40, 34.4%) 및 UCI 보고값(33.5%)보다 **소폭 개선**. 상위 모델 간 차이는 표준편차(±6\~7) 이내 |

## 4. EDA 요약 (`secom_eda.ipynb`)
1. **상수 컬럼 116개 제거** (590 → 474)
   - 전부 결측이 1\~24개 섞여 있어, 결측 여부 자체가 불량 신호인지 **Fisher 정확검정**으로 확인 → 7개 결측 패턴 모두 비유의(최소 p = 0.24) → 플래그 없이 삭제
2. **결측 분석**: 결측 > 50% 컬럼 28개(결측 패턴 기준 약 5개)에 Fisher 검정 + BH 보정
   - ⭐ **f72, f73, f345, f346**: 결측 시 불량률 4.5% vs 관측 시 8.8% (p ≈ 0.0008, BH q ≈ 0.004) → **결측 플래그 후보**
3. **중복 정리**: |r| > 0.95인 쌍 329개 → 계층적 군집(거리 = 1 − |r|, average linkage, t = 0.05) → 그룹마다 **결측 최소 변수** 1개를 대표로 (474 → 282, `X2`)
4. **라벨 관련성 (참고용)**: 라벨 상관 최대 |r| ≈ 0.17 → 단일 변수로는 약함. 상관·상호정보량(MI) 둘 다 상위인 후보 13개: f59, f103, f247, f111, f510, f205, f33, f348, f28, f21, f125, f129, f385
5. **시간 흐름**: 표본이 충분한 주 기준으로 8월 주별 불량률 10\~21% → 9월 이후 1.5\~4% → **공정 드리프트**
   - 시간순 분할(10/2 기준) 앞 80% vs 뒤 20% 불량률은 6.9% vs 5.4%(p = 0.38)로 차이가 작음. 저불량기(9월)가 학습 구간에 이미 포함되기 때문이다. 따라서 시간순 성능 하락은 불량률보다 **센서 패턴 변화** 때문일 가능성이 크다 → 오토인코더 실험(6-2)에서 일부 센서의 분포 변화를 확인

> **전체 데이터 사용 범위**: 상수 제거와 상관 군집은 라벨을 쓰지 않는 비지도 단계라 전체 데이터에서 수행했다. 라벨을 쓴 분석(Fisher 검정, 라벨 상관, MI)은 **참고용**이며, 변수 선택은 전부 `Pipeline` 안에서 fold마다 수행한다.

## 5. 모델링 설계 (`secom_model.ipynb`)

### 공통 원칙
- **입력** `X2`(282개), **라벨** `yb`
- **누수 방지**: 결측 대체·스케일링·변수 선택·SMOTE·임계값 결정은 모두 `Pipeline` 안에서 학습 fold에만 fit
- **두 가지 검증**
  - 랜덤 CV: `RepeatedStratifiedKFold(n_splits=10, n_repeats=5, random_state=42)` → 50 fold의 평균
  - 시간순: timestamp 기준 앞 80% 학습 / 뒤 20% 테스트 → 공정 변화 상황의 성능 (테스트 구간 불량 17개라 흔들림이 큼)
- **결측 플래그**: 학습 fold에서 결측 > 50%인 컬럼만 `컬럼_na`(0/1) 생성, 패턴이 같은 플래그는 하나만 유지 → 이후 중앙값 대체
  - LightGBM은 NaN을 그대로 입력
- **불균형**: `class_weight="balanced"`. SMOTE는 비교용
- **하이퍼파라미터**: inner 5-fold `GridSearchCV` (nested CV). C 9개(1e-3 \~ 10)
- **임계값**: 필요한 모델은 `TunedThresholdClassifierCV`(inner CV, balanced accuracy 기준)로 결정
- **지표**: **BER**(= 1 − balanced accuracy, 메인) + 불량 recall + PR-AUC + F1
  - PR-AUC의 무작위 기준값 = 불량 비율 ≈ 0.066

### 비교 모델
| 모델 | 설정 |
|---|---|
| 기준선 | 중앙값 대체 → 표준화 → F-test 상위 40개 → 로지스틱 (balanced) |
| Ridge / Lasso / Elastic Net | 결측 플래그 → 대체 → 표준화 → 로지스틱. `l1_ratio` 0 / 1 / 0.5, solver lbfgs / liblinear / saga |
| LightGBM | NaN 그대로, balanced, 과적합 완화(`num_leaves=15`, `learning_rate=0.03`, `n_estimators=300`, subsample 0.8, colsample 0.5, `reg_lambda=1`), 임계값 튜닝 |
| SMOTE + Elastic Net | imblearn Pipeline, fold 안에서만 SMOTE, class_weight 없음 |
| MLP | sklearn `MLPClassifier(64)`, early stopping, 임계값 튜닝 |

> Elastic Net의 `l1_ratio`는 사전 실험 결과에 따라 0.5로 고정했고, 임계값 튜닝 효과는 계산 비용 때문에 시간순 검증으로만 확인했다.

### 해석
1. **랜덤 CV: 소폭 개선, 상위권은 사실상 동률**. Lasso·LightGBM·EN·SMOTE+EN이 31\~33%로 기준선(34.4%)과 UCI 보고값(33.5%)보다 낮다. 다만 상위 모델 간 차이는 표준편차(±6\~7) 안이다.
2. **시간순 검증에서 순위 역전**: 가장 단순한 기준선이 BER·recall·PR-AUC 모두 1위다. LightGBM은 PR-AUC가 0.240 → 0.107로 급락했고, **SMOTE + EN은 recall 0%로 완전히 무너졌다**. 합성 샘플에 맞춰진 경계가 분포 변화에 가장 취약했던 것으로 보인다. → **랜덤 CV 최고 모델이 공정 변화 상황의 최고 모델은 아니다.**
3. **임계값 가설 검증 → 기각**: Ridge·EN은 시간순 PR-AUC(구별력)는 기준선과 비슷한데 recall만 급락했다. 그래서 임계값 문제로 보고 학습 구간에서 임계값을 튜닝했지만, 고른 값(0.469)이 0.5와 거의 같아 개선이 없었다. **과거 데이터만으로는 미래에 점수 분포가 얼마나 밀릴지 알 수 없다** → 현장에서는 **최근 라벨 데이터로 임계값을 주기적으로 재조정하거나 재학습**해야 한다.
4. **임계값 문제 사례 (LightGBM)**: 기본 임계값 0.5에서는 recall 0%(BER 50%)였지만 PR-AUC는 0.214였다. inner CV로 고른 임계값(약 0.03)을 적용하자 BER 31.8%가 됐다. 구별력은 있었는데 판정 기준이 맞지 않았던 것이다.
5. **Lasso의 C 민감도**: fold별 사용 변수 수가 C = 0.01일 때 6\~10개, C = 0.0316일 때 52\~65개로 두 덩어리로 갈렸다. 평균(28개)보다 **선택 빈도 80% 이상인 5개**가 안정적인 결과다.
6. **MLP**: CV·시간순 모두 하위권이다. 원인을 추적해 보니 early stopping이 정확도 기준이라 불균형 데이터에서 조기 종료되고 있었다 → 아래 6-2 개선 실험

## 6-2. MLP · 오토인코더 개선 실험 (`secom_dl.ipynb`)
가설을 하나씩 세우고 **한 가지만 바꿔서** 같은 fold(10-fold × 1회)로 비교했다. 판단은 CV 기준이다. 비교 기준은 같은 fold의 기존 MLP(M0, BER 39.9%, PR-AUC 0.186)이다.

| 실험 | 가설 | 변경 | CV BER (%) | CV PR-AUC | 판단 |
|---|---|---|---|---|---|
| M0 | – | 기존 MLP (early stopping) | 39.9 ± 8.6 | 0.186 | 기준 |
| **M1** | early stopping이 너무 일찍 멈춰 학습 부족 | early stopping 끔, 200 epoch | **34.3 ± 6.3** | **0.193** | ✅ **지지.** 정확도 기준 조기 종료가 원인. 다만 학습 loss ≈ 0, 임계값 0.01 → 과적합 신호 |

| **양품 오차가 불량보다 큼** (비율 < 1) | f111 (0.33), f109·f110 (0.38), f6 (0.62), f485 (0.77) | 테스트 구간 양품 자체가 학습 구간의 "정상"과 달라짐 → **센서 분포 변화(드리프트)의 직접 증거** (f109\~f111은 결측 65% 그룹이라 결측 패턴 변화가 섞였을 수 있음) |

**결론**
- **MLP**: 원인(정확도 기준 early stopping)을 찾아 고쳐서 39.9 → 34.3%로 기준선 수준까지 끌어올렸다. 오버샘플링·규제 강화로는 더 오르지 않았고, 데이터 규모(불량 104개)의 한계로 최상위 모델(Lasso·LightGBM·EN)에는 못 미쳤다.
- **오토인코더**: 구조(병목)는 영향이 없고 전처리(이상치 처리)는 약간 도움이 됐다. 하지만 라벨 없이 282개 센서를 똑같이 다루기 때문에, 불량에서 튀는 센서가 분류 모델의 핵심 센서(f59, f21)와 거의 겹치지 않는다 → **불량과 무관한 센서가 대부분인 데이터에서는 비지도 이상탐지보다 지도학습이 적합**하다.
- 부수 효과로, 오토인코더가 **드리프트가 일어난 센서**를 짚어냈다(f109\~f111, f6, f485).

## 8. 한계와 다음 단계
- 센서 이름이 익명(f0\~f589)이라 공정 의미는 해석할 수 없다 → 실제 현장이라면 도메인 담당자와 f59·f21 확인이 다음 단계
- 시간순 테스트 구간의 불량이 17개뿐이라 시간순 수치는 경향 위주로 해석
- 시간순 성능 하락의 원인(센서 분포 변화)은 오토인코더 실험에서 일부 센서(f109\~f111, f6, f485)로 확인됐다 → 학습/테스트 구간의 센서 분포를 직접 비교(분포 그래프, KS 검정)하면 더 확실해진다
- MLP의 alpha 탐색(M3)은 임계값 0.5 기준 점수로 골라서 부정확했을 수 있다 → PR-AUC 기준 재탐색은 추후 과제
- 오토인코더 개선 아이디어: fold 안에서 L1로 고른 소수 센서만 입력해 불량과 무관한 변동을 줄이기
- **f72 결측 비율이 50.7%로 플래그 기준(50%)에 걸쳐 있다**: 랜덤 CV fold에서는 플래그가 생기지만 시간순 학습 구간에서는 생기지 않는다 → 기준값 민감도 확인 필요
- 개선 후보: 최근 구간 재학습 / 시간 가중 학습, 드리프트 감지 후 임계값 재조정, 정식 stability selection
- SECOM은 행마다 제품 하나인 표 데이터라 순서·공간 구조를 전제하는 RNN·CNN은 적용하지 않았다
